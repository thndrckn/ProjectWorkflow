# Changelog

One short entry per change number, newest first. This is the master list of ProjectWorkflow change numbers (`PWF-###`). The full detail of each change lives in its plan (`docs/plans/`) and review record (`docs/reviews/`).

PWF-001 to PWF-026 were made inside DisneyTripPlanner as DTP-086 to DTP-111 and moved here by PWF-027; `docs/HISTORY.md` maps each one to its original number and commit. Their entries are unchanged apart from the number, so where they say "this project", "CLAUDE.md" or "master", they mean DisneyTripPlanner at the time, and any other DTP number in them (such as DTP-068 or DTP-085) is a DisneyTripPlanner change.

## [0.1.1] - 2026-10-30

- PWF-033 (fix) After PWF-032, a plugin install left `.claude/settings.json` showing as modified in git with no change to its content: the install writes the file with plain (LF) line endings, while git on Windows checks it out with Windows ones. `.gitattributes` now says that file is always LF, and `adopt.sh` adds the same line to the project it sets up (once, keeping the project's own lines) and tells you the file needs committing. In a project adopted earlier that already has the file checked out with Windows endings, run `git add --renormalize .claude/settings.json` once if git still lists it.
- PWF-032 (fix) The workflow's two plugins are now installed for one project at a time, not for every project. `adopt.sh` installs them at project scope for the project it adopts and removes the copies installed for every project; it also stops if the project's CLAUDE.md has no Workflow heading, if the plugin list cannot be read, or if Matt's official copy is installed at any scope. The edit guard and the plan-mode block now do nothing in a project whose CLAUDE.md has no Workflow section (new shared `hooks/adopted.sh`). This repo's own plugin settings are committed in `.claude/settings.json`. The trunk lock is unchanged. Projects adopted earlier lose the workflow's commands and guard until `adopt.sh` is run on them again; the guard change reaches projects at the next build.
- PWF-031 (fix) The review gate accepts `Manual` as the result of a manual check, so a manual check no longer blocks check-in (it had to be changed to `Pass` first). A manual check that was run still says `Pass` or `Fail`; `Fail` still fails, and anything else (blank, "TBD", "Manual-fail") is still refused. `/code-change` says so. Adds a backlog item about the "Original request (set aside)" label in plans.
- PWF-030 (chore) In ProjectWorkflow itself the trunk lock now means one thing: the repo's own `githooks/` folder. `adopt.sh` refuses to run on the workflow's own repo or any of its worktrees and points to `bash githooks/install-trunk-lock.sh` (other projects keep `release/githooks`), so it can no longer leave git pointing somewhere `/merge-change`'s lock check reads as off. CLAUDE.md's Trunk lock line says which is which.
- PWF-029 (chore) Finished adopting the workflow in this repo: Matt's one-time setup is done (local markdown tracker, default triage labels, single-context docs, in `docs/agents/`), `docs/POLICY.md` now describes the new commands and the Light/Full review instead of `/plan-change`, `/commit-change` and three review rounds, and the hand-edit rule for the shared policy is gone. CLAUDE.md gains PowerShell forms of the checks, the lock install and `adopt.sh`, and `test-adopt.sh` checks that `adopt.sh` accepts this repo's own setup.

## [0.1.0] - 2026-10-26

- PWF-028 (feat) Rebuilt the workflow on Matt Pocock's skills as a plugin: the repo root is the plugin, and ProjectWorkflow's own marketplace pins Matt's plugin at a fixed commit. New commands are /design-change, /plan-small-change, /plan-large-change (tickets numbered NNN.1, NNN.2, …), /code-change (Matt's code-review, plus our Correctness reviewer for Full, then one narrow re-review), /merge-change and /build-changes (no review step); the old /plan-change and /commit-change are gone. The trunk lock's checker is rewritten for one smaller review record, accepts ticket numbers, and refuses any Findings line that is not "None" or a well-formed finding; the guard no longer checks shell commands. Adds a short CLAUDE.md, .gitattributes, the shared policy and process backlog (moved in from the shared conventions folder), adopt.sh for setting up a project, and release/ (a worktree at a local tag). Done by hand, because the workflow cannot check in its own rebuild.
- PWF-027 (chore) Recorded the extraction from DisneyTripPlanner-archive: `docs/HISTORY.md` maps PWF-001 to PWF-026 to their original DTP numbers and lists what was left out and why, the renumbering script is kept in `docs/history/`, this changelog keeps only the workflow entries, `design.md` is added unedited, and DisneyTripPlanner's app-side workflow files are kept as examples in `reference/disneytripplanner/`. Done by hand, because the workflow is not set up in this repo yet.
- PWF-026 (chore) /code-change now reports file overlap with other open changes in one line and carries on instead of asking; /commit-change, on any conflict other than CHANGELOG.md, still stops with the merge aborted, but now shows each conflicted file with the resolution it proposes and why, and applies nothing until you answer.

- PWF-025 (chore) Prepared the workflow for renaming the default branch from master to trunk: the guard now protects trunk, master and main, the master lock is renamed the trunk lock (files, scripts, tests, skills, wording) and reads CLAUDE.md's lock lines under either label, and living docs say "the default branch". The rename itself (local, GitHub, and the CLAUDE.md branch name and lock labels) is a by-hand checklist in the plan, run after check-in.
- PWF-024 (chore) /plan-change now offers a fourth backlog choice, "include it in this change" (the item joins the plan with its own requirement and test and is listed under "Backlog items fixed"; recommended only when it touches the same files or area as the change, otherwise keeping it queued is recommended), and shows `/rename <NUMBER>` right after announcing the change number, again if the number moves. The backlog file's introduction and the shared policy's sentence (edited by hand) list all four choices.

- PWF-022 (chore) The shared conventions folder (the shared policy and process backlog) is now edited by the user by hand only, as a stated rule: a new "Shared conventions folder" line in CLAUDE.md names it, the guard hook blocks Claude's edit tools and shell writes there on every branch (best-effort), plans get a "Policy edits for you to make by hand" section with the exact old and new text, and /code-change saves a before-copy, stops for the user's confirmation and shows the reviewers both versions. Without the CLAUDE.md line only the edit tools are blocked, and only while the project is on master.
- PWF-021 (chore) The master lock now reads the re-review part of a review record exactly instead of by keyword: each finding carries a "Re-review (round N): accepted" line, a fixed failed requirement gets one naming it, and each round ends with "Round N clean: yes" or "no". New records carry the header "accountability 2"; CLAUDE.md's new "Review format 2 required from" line (PWF-024) makes it mandatory from that change on, and a check-in cannot raise or remove it. The record template, the re-reviewer brief and the check-in gate wording follow, and the temporary keyword-reading note is gone from the design decisions.
- PWF-023 (chore) Worktree setup now runs `npm ci`, so a worktree never rewrites the lockfile; CLAUDE.md also gives the PowerShell form of the lock setup, lock turn-on and guard test commands, since bash isn't on the PowerShell path.
- PWF-019 (chore) The rules in CLAUDE.md and the shared policy that a program can check are now checked on every change: lint enforces the TypeScript ones (invoke only in api.ts, thin api.ts wrappers, no new Date(text), no browser dialogs, no inline styles, no frontend network calls, lucide-react icons only), and a new `npm run check:conventions` covers SQL, network code, command registration, types.ts vs models.rs, migrations and the dark-only palette; `npm run test:conventions` proves each rule catches a violation.
- PWF-017 (chore) Added the master lock: a git hook that refuses any update of master that is not a proper check-in (every change from PWF-016 on needs a review record that passes the commit-change gate; release commits may touch only the version files and the changelog), however the commit arrives. One shared checker serves the hook and /commit-change, which now also numbers its catch-up merge; /commit-change and /build-changes stop if the lock is off, and the guard hook stops Claude from switching it off.
- PWF-020 (chore) Every /plan-change play-back now uses one fixed format: a normal message with a Summary, the Requirements and the Decisions so far, ending in "Is that right?" as plain text (no question box); a corrected play-back says at the top what changed.
- PWF-018 (chore) /code-change now loads the worktree tools, enters the worktree and checks the folder and branch, stopping if it can't, so /commit-change can step out of it from the same chat; /commit-change loads the tools too.
- PWF-016 (chore) A by-design reason tied to one spot in the code now goes in a "why" comment at that spot, a project-wide one in docs/DECISIONS.md; /code-change and the Standards reviewer follow the rule, and the shared policy states it.
- PWF-015 (chore) Each change is now coded in its own worktree, so several can be coded at once in separate chats: /plan-change claims change and migration numbers at once, /code-change works in a worktree with its own empty database and dev-server port, /commit-change merges from it, resolves a changelog-only clash and removes it, /build-changes builds what is merged while others are open, and the guard hook protects master from every folder.
- PWF-014 (chore) When "Plan it now" sets aside your original /plan-change request, the plan now records it word for word, and /commit-change's final report ends with it as a ready-to-paste /plan-change command.
- PWF-013 (chore) The inert plan-renaming script, its after-plan-mode hook entry and the plan-folder setting are removed from the project settings; plan mode stays blocked. The matching backlog entry is removed.
- PWF-012 (chore) The shared policy's change-number and commit-message examples now use the neutral `ABC-085` instead of this project's real `DTP-085`; the matching backlog entry is removed.
- PWF-011 (chore) Three plan rules added to /plan-change and the shared policy (no made-up changes in tests, workflow changes are chore, no project-specific wording in shared skills and hooks), and the skills' stack wording moved into new CLAUDE.md lines (lockfile commands, installer location, data folder).
- PWF-010 (chore) The master-edit guard now also checks shell commands (Bash and PowerShell) on master: only an allow-list of git subcommands passes, and writes into the project are blocked; best-effort, with a test script.
- PWF-009 (chore) Added docs/BACKLOG.md for review findings that were neither fixed nor explained, and retired KNOWN_ISSUES.md; every /plan-change now asks about each backlog item first (plan it now, keep it queued, or accept it).
